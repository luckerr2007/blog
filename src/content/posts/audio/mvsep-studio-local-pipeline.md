MVSEP 的分离质量不错，但网页端用起来有几个绕不过去的问题：官方 API 不返回 CORS 头，浏览器不能直连；结果文件链接过一段时间就失效；模型列表有 128 个，全英文，参数也看不懂。再加上我习惯先从网易云找歌，整个流程就变成了「网页搜歌 → 下载 → 上传到 MVSEP → 等 → 再下载分轨」，来回折腾。

MVSEP Studio 就是把这几个步骤接在本机。它不是分离算法，真正干活的是 MVSEP 的服务器；这个项目负责代理、排队、轮询、缓存和试听。

## 两个外部服务，一个本地进程

工作区分成两块：

- `mvsep-studio/`：Vue 3 前端 + Express 服务，默认 `127.0.0.1:8787`；
- `Netease_url/`：上游开源的网易云解析服务，Flask，默认配置里指向 `127.0.0.1:5001`。

开发时前端走 Vite 的 `5173`，`/api` 代理到 8787；生产模式只开 8787，Express 同时提供 API 和构建好的前端。Studio 明确 `app.listen(PORT, '127.0.0.1')`，只接受本机连接。网易云那边由上游 Flask 决定监听地址，`run-netease.py` 没有改 host，启动后要确认实际绑定的是回环还是 `0.0.0.0`，别把 5001 暴露到局域网。

网易云原本默认 5000 端口，但 macOS 的隔空播放接收器会占用它。这里没有改上游源码，而是在 `tools/netease/run-netease.py` 里导入 `main` 后改掉 `config.port`，再启动：

```python
import main as app_main
app_main.config.port = PORT
app_main.start_api_server()
```

上游仓库保持只读，后面同步版本省事。

`start.sh` 做了九件事，顺序不能乱：检查 Node ≥ 20 和可用的 Python；只在缺依赖时安装；只在 `dist` 不存在或源码比它新时构建；探测端口，能复用就复用，不能复用就清理；启动网易云并等 `/health`；启动 Studio；打开浏览器；前台监视两个端口；收到 INT/TERM 时先杀记录的 PID，再按端口兜底。

最后一步是必要的。`nohup` 拿到的 `$!` 有时是包装脚本的 PID，真正的 node/python 进程在它下面；只杀父进程会留下孤儿。按端口再扫一遍虽然土，但可靠。

## 一个任务有 11 个阶段

MVSEP 的上游状态不是一条直线，中间夹着排队、分发、分块处理、合并。工作台把这些拆成 11 个阶段，每个阶段有固定的进度区间：

| 阶段 | 进度区间 | 子进度来源 |
| --- | --- | --- |
| `pending` | 0–2 | 固定 |
| `resolving` | 4–14 | 解析请求 |
| `downloading` | 14–34 | 已下载字节 / 总字节 |
| `submitting` | 34–44 | 提交请求 |
| `waiting` | 44–58 | 队列名次 |
| `distributing` | 58–68 | 已完成分块 / 总分块 |
| `processing` | 68–90 | 已完成分块 / 总分块 |
| `merging` | 90–98 | 上游文案里的百分比或分数 |
| `done` / `failed` / `canceled` | 100 | 终态 |

进度只增不减。同一阶段反复查到相同值，只更新进度，不写时间线；换阶段才写一条。否则轮询会把时间线刷成几百条重复记录。

任务记录存在 `server/data/store.json`，最多保留 300 条。每次变更不是立刻落盘，而是 120ms 防抖后写一次。这个文件同时存设置、任务和缓存，没有数据库，也没有迁移脚本；字段靠 `deepMerge(DEFAULT_STORE, raw)` 补默认值。

服务重启时要对账。崩溃时留下的 `mirroring` 标记会被清掉；活跃但还没有 MVSEP hash 的任务，说明中断发生在本进程，标成失败；已经有 hash 的任务继续轮询，因为上游可能还在跑。

## 轮询器只有一个 setTimeout

没有引入队列库。一个会自我重排的 `setTimeout` 就够了：

- 有活跃任务时按 `pollIntervalMs`（默认 5 秒）跑，空闲时 30 秒；
- 每轮最多查 6 条，同时给令牌桶留 5 次额度，避免把 120 次/分钟的配额一次抽干；
- `waiting` 阶段乘 3、`pending` 乘 4，排队名次变化慢，没必要每轮都查；
- 手动刷新和轮询同时命中同一条任务时，用 `inflight` Map 合并成一次请求；
- 新任务提交后 `kickPoller(500)` 把下一轮提前，否则用户要盯着「已进入队列」等半分钟。

查询失败不判任务失败。上游抖动很常见，直接判死会让用户重跑，白白再烧一次额度。失败只累计次数、写进时间线，继续重试。

`not_found` 单独处理：刚提交的一两分钟，上游经常还没登记，给 3 分钟宽限期；超过才失败。

## 和 MVSEP 通信的几个约束

区域必须一致。创建、查询、取消、下载要落在同一个主机上，任务记录里保存提交时的 `region`，后续请求都带着它，不跟当前设置走。

限流按官方 120 次/分钟留了余量，做成 100 次/分钟的滑动窗口。只有幂等的 GET 会自动重试 3 次；create、cancel、delete 失败就如实报错。POST 超时后重发可能已经在云端建了任务，重复扣额度比失败更糟。

MVSEP 的错误位置不统一：创建类接口放在 `errors[]`，结果类放在 `data.message`，参数错误在顶层 `message`。客户端把三种都抽出来，`not_found` 作为合法状态返回，不抛异常，否则轮询会断。

文件字段也有两套：`files` 可能是数组或对象，大小可能是精确的 `bytes` 或字符串 `size`。这些都在客户端归一化，前端拿到的结构是稳定的。

回源下载只允许 `mvsep.com` 和 `*.mvsep.com`。这条白名单在试听、下载、ZIP、镜像四个入口都调用，防止本地服务被当成开放代理。下载先写 `.part`，完成再改名，进度按字节回调。

密钥后来做成了池。提交新任务时在启用的 key 之间轮询，额度用完冷却 10 分钟，密钥无效冷却 30 分钟；查询和取消用创建任务时的 `tokenId`，避免拿错账户。前端显示的是各 key 免费额度的总和。

这里有个需要处理的遗留问题：`config.mjs` 的默认配置里还留着一个硬编码 token 字面量。无论它是否有效，都不应该出现在源码里，分享或开源前应删掉，并改成首次启动必须自行填写。文档里还写着「单 token」，代码已经是池，两者也需要对齐。

## 网易云这一段比想象中麻烦

`/api/netease/resolve` 有副作用：它会让 Netease_url 自己下载文件并返回绝对路径。利用这一点，本机可以直接把同一个文件路径交给 MVSEP，省掉一次复制；慢路径才流式落盘到 `downloads/`。

缓存有两层：进程内的解析缓存 15 分钟，命中后还要确认文件仍然存在；`store.json` 里的 `cache.neteaseFiles` 是持久索引。两者都不信任「曾经解析过」这件事，文件没了就重新来。

端口冲突有专门识别：如果 5001 返回 403 且 `Server: AirTunes`，说明连到了隔空播放，不是网易云服务。前端会提示改端口，并自动探测 5001/5000/5002。

音质上限由 `cookie.txt` 决定。模板自带的 Cookie 基本只能拿 320kbps，无损、Hi-Res、超清母带要看账号权限；失败会自动降级，不会让任务卡死。

网易云上游还有几个已知的不一致：`qr_login.py` 的返回类型和当前 `QRLoginManager` 对不上，交互扫码实际跑不通；Docker `entrypoint.sh` 的参数没有 argparse 接收；`/search` 的 `offset`/`type` 解析了但没下传。集成时按实际行为写，不要照 README 猜。

## 结果必须落到本地

MVSEP 的结果链接会过期，所以分离完成后默认把分轨镜像到 `server/data/results/<jobId>/`。镜像失败只写时间线，不把任务判失败；用户仍然可以回源试听。

试听接口优先发本地文件，未镜像时才带 Range 回源。ZIP 用 archiver 流式打包，本地文件直接进包，未镜像的先落 `tmp/`，不会把整张专辑读进内存。

前端没有用 UI 框架。波形是 Canvas 自绘，播放用 Web Audio 解码，峰值按 URL 缓存在模块级 Map。多轨同步靠一个全局播放器注册表：`playGroup` 以第一条轨的 `currentTime` 为基准，误差超过 60ms 才纠正，避免多轨来回抖动。

模型选择器里放了一份中文知识库：约 60 个常用模型的人工说明、10 张场景卡、30 多条参数白话解释、70 多条中英文检索词映射。目的不是翻译全部 128 个模型，而是让「只要人声伴奏」「拆鼓和贝斯」这种需求能直接落到几个候选上。

## 已知问题

- 服务只监听回环地址，没有登录；不要把 8787 或 5001 暴露到公网。
- Netease_url 自身无鉴权且 CORS `*`，只能接受它跑在本机。
- `store.json` 明文保存 MVSEP token，文件权限和备份要自己管。
- 默认配置里的硬编码 token 应删除。
- 文档里的旧路径还是 `~/Documents/项目/MVSEP`，实际已经移到 `audio/MVSEP`。
- 它不提供分离算法，MVSEP 不可用时整个核心流程就不可用；本项目的价值在编排和本地缓存。
