整理储物间的时候，翻出一箱大学时买的 CD。有些是打口碟，有些是演唱会现场，还有几张是当年为了某一首歌买的整张专辑。盒子受潮，封面有霉点，但碟面大多还能读。

流媒体当然更方便，但这些已经买过的音乐，至少应该有一个能长期保存的副本。于是花了一个周末，把它们抓成 FLAC。

## 工具

- `abcde`：抓轨和编码的前端，负责调用 cdparanoia、flac 和元数据服务；
- `cdparanoia`：带纠错的抓轨工具，遇到划痕会比普通读取更耐心；
- `flac`：无损编码；
- `beets`：导入音乐库，匹配 MusicBrainz，统一命名和封面。

macOS 上直接 `brew install abcde cdparanoia flac beets`，Linux 用包管理器装。

## 配置

`~/.abcde.conf` 里改几项：

```ini
OUTPUTTYPE=flac
CDDBMETHOD=musicbrainz
EJECTCD=y
OUTPUTDIR=~/Music/rips
```

抓一张碟：

```bash
abcde -d /dev/sr0
```

macOS 的设备路径不一定是 `/dev/sr0`，先用 `drutil status` 看，或者让 `abcde` 自己找。第一次跑建议加 `-n` 只做试运行，确认曲目和编码参数没问题再正式抓。

## 元数据

`abcde` 会从 MusicBrainz 拉曲目信息，但老唱片、打口碟和现场专辑经常匹配不上。抓完用 `beets` 导入：

```bash
beet import ~/Music/rips
```

`beets` 会逐张确认匹配结果，可以改专辑名、艺术家、曲序，也能下载封面。命名规则写在 `~/.config/beets/config.yaml`：

```yaml
paths:
  default: $albumartist/$album%aunique{}/$track $title
```

多碟专辑要特别注意 `%aunique{}`，否则两张碟会混到同一个目录里。

## 遇到的问题

**划痕。** 有两张碟在第三、四轨反复报错。用 `cdparanoia -B` 单独抓那几轨，放慢速度，最后还是有几秒爆音。能接受就留着，不能接受就放弃，不值得为一张碟折腾一晚上。

**元数据。** 打口碟的条码经常被剪掉，只能手动搜专辑名。现场专辑的曲目时长和 MusicBrainz 对不上，`beets` 会反复询问，最后选了“作为不完整专辑导入”。

**封面。** 有些封面分辨率很低，有些根本没有。后来统一用 600px 以上，低于这个尺寸的宁可留空。

**存储。** 一张 CD 抓成 FLAC 大约 250–400MB，一箱下来几十 GB。放在家里的 Ubuntu 服务器上，用 Navidrome 串流，手机和电脑都能听。

## 结果

最后抓了大约 120 张，成功 110 多张，剩下的要么划得太厉害，要么是数据碟。整理完的音乐库按“艺术家/专辑/曲目”存放，封面和歌词放在同一目录，备份到外接硬盘。

这件事的意义不在于“音质比流媒体好”，而在于把已经拥有的东西整理清楚。流媒体下架一张专辑只需要一个版权变更，而硬盘里的 FLAC 不会。

抓完的 FLAC 放在[家里那台 Ubuntu 服务器](/posts/misc/2022-10-03-home-server/)上，用 Navidrome 串流。音频处理的习惯则是从[批量处理录音](/posts/misc/2024-01-21-ffmpeg-audio/)那时候留下来的。
